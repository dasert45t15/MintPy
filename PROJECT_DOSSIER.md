## 1. Концепция и назначение проекта

**MintPy** — это мультимедийный дзэн-аудиоплеер для учёбы, работы, программирования и концентрации.  
Главная идея: отсутствие рекламы, платных подписок и отвлекающих алгоритмических лент; создание уютной аудиовизуальной атмосферы (Lo-Fi, Zen, эмбиент, виниловый проигрыватель, частицы сакуры).

### Ключевые возможности:
* **Двойная платформа:** Полноценный десктопный клиент (Windows/Linux/macOS) и автономное мобильное приложение (Android APK).
* **Стриминг и локальный звук:** Воспроизведение локальных треков, онлайн-поиск музыки и прямое воспроизведение из открытых веб-источников (YouTube Innertube без авторизации).
* **Импорт плейлистов:** Перенос публичных альбомов и плейлистов из **Яндекс Музыки**, **Spotify** и **YouTube Music** с автоматическим поиском и стримингом.
* **Атмосферный интерфейс:** 6 уникальных визуальных стилей (`Zen`, `Lo-Fi`, `Synthwave`, `Ocean`, `Forest`, `Aurora`) со светлой и тёмной темами.
* **Движок частиц Canvas:** Интерактивные фоновые эффекты в реальном времени (лепестки сакуры, пар кофе, звёздная пыль, пузыри, светлячки).
* **Виниловый проигрыватель:** Реалистичная пластинка с коническим градиентом отражения света и вращением во время воспроизведения.
* **Звуки природы (Ambient Deck):** Микшер звуков дождя, костра, волн, ветра, леса, белого шума.
* **Таймер сна (Sleep Timer):** Плавное затухание громкости через заданное время.
* **Тексты песен (Lyrics):** Получение синхронизированных и статических текстов.

## 2. Архитектура: Разделение на ПК и Mobile

В проекте реализовано **полное физическое разделение** кода для ПК и мобильной версии, чтобы мобильный билд оставался легковесным, не зависел от Node.js/Electron и не содержал неработающего ПК-функционала.

```
                      [ Исходный код MintPy ]
                                 │
         ┌───────────────────────┴───────────────────────┐
         ▼                                               ▼
   [ ПК Версия ]                                   [ Mobile Версия ]
   Каталог: src/                                   Каталог: src_mobile/
   Среда: Electron + Node.js                       Среда: Android WebView (Chromium)
   Бэкенд: app.js (IPC, yt-dlp, proxy)             Мост: mobile-bridge.js (localStorage, Innertube)
   Сборщик: electron-builder                       Сборщик: scripts/build-android-apk.py
   Выход: releases/*.exe                           Выход: releases/MintPy-v5.3.8.apk (~15.7 MB)
```

## 4. Подробное устройство подсистем

### 4.1. Мобильный мост (`src_mobile/mobile-bridge.js`)
Это «сердце» мобильной версии. В отличие от ПК, где работает Node.js и yt-dlp, на мобилке:
1. **Хранилище:** Используется `localStorage` с ключами:
   * `mintpy_settings`: настройки (стиль, тема, нормализация, эквалайзер, кроссфейд).
   * `mintpy_favorites`: массив избранных треков.
   * `mintpy_playlists`: массив пользовательских плейлистов со списками треков.
   * `mintpy_history`: история последних 100 воспроизведений.
   * `mintpy_queue`: текущая очередь воспроизведения и индекс трека.
2. **Поиск музыки:** Делает POST-запрос к `https://www.youtube.com/youtubei/v1/search` через асинхронный fetch с таймаутом `AbortSignal.timeout(5000)`. Если WebView блокирует CORS, автоматически срабатывает fallback на нативный Java-метод `AndroidNative.postJson(...)`.
3. **Прямое воспроизведение:** Для `yt:VIDEO_ID` отправляет запрос к `youtubei/v1/player` с клиентом `ANDROID` / `WEB` и извлекает прямую аудиоссылку (`streamingData.adaptiveFormats` / `audio/mp4`). Полученная ссылка скармливается нативному HTML5 элементу `<audio>`.
4. **Импорт плейлистов (`importPlaylistFromUrl`):**
   * **Spotify:** Парсит embed-страницу (`open.spotify.com/embed/...`), достает JSON из `<script id="__NEXT_DATA__">`, извлекает список треков и создает поисковые плейсхолдеры `yt:ytsearch:Artist - Title`.
   * **YouTube / YouTube Music:** Парсит плейлист по ID через `youtubei/v1/browse` (`VL` + `listId`), извлекая элементы `lockupViewModel` и `playlistVideoRenderer`.
   * **Яндекс Музыка:** Запрашивает открытые хендлеры `handlers/playlist.jsx` и `handlers/album.jsx` или парсит `schema.org/MusicPlaylist` из HTML.

### 4.2. Нативный Android контейнер (`build_android/.../MainActivity.java`)
* Наследует `Activity`. Разворачивает `WebView` на полный экран (NoActionBar, Fullscreen).
* Настройки WebView: `setJavaScriptEnabled(true)`, `setDomStorageEnabled(true)`, `setDatabaseEnabled(true)`, `setAllowFileAccessFromFileURLs(true)`, `setAllowUniversalAccessFromFileURLs(true)`.
* Встроенный класс `AndroidBridge` с аннотацией `@JavascriptInterface`:
  * `postJson(url, body)` / `postJsonWithHeaders(url, body, headersJson)` — синхронный HTTP POST через Java `HttpURLConnection` для обхода ограничений сети.
  * `getUrl(url)` / `getUrlWithHeaders(url, headersJson)` — синхронный HTTP GET.
* Поддержка аппаратного ускорения для плавной работы 60 FPS CSS-анимаций и Canvas.

### 4.3. Автономный сборщик APK (`scripts/build-android-apk.py`)
Работает **без Android Studio и без Gradle** прямо в Windows:
1. Копирует исходники `src_mobile/` и ассеты `assets/themes/` во временную папку ассетов APK.
2. Генерирует `R.java` и компилирует ресурсы через `aapt2 compile` + `aapt2 link`.
3. Компилирует Java-код (`MainActivity.java`) с помощью встроенного JDK 17 (`javac.exe`).
4. Транслирует `.class` байткод в `classes.dex` через Google `d8.bat`.
5. Упаковывает всё в ZIP-архив утилитой `jar.exe`.
6. Выполняет 4-байтовое выравнивание через `zipalign.exe`.
7. Подписывает APK схемами v2/v3 через `apksigner.bat` с ключом `mintpy-debug.keystore`.
8. Результат: готовый APK кладётся в `releases/MintPy-v5.3.8.apk` всего за 3–5 секунд!

### 4.4. Визуальные стили и фоны
В плеере 6 стилей оформления:
* `zen` (Дзэн 🎋): бамбук, сад камней, бонсай, лепестки сакуры.
* `lofi` (Lo-Fi ☕): тёплый плед, кружка кофе, кассета, поднимающийся пар.
* `synthwave` (Synthwave 🌆): неоновый ретровейв, закат, мерцающие звёзды.

* `aurora` (Aurora ✨): северное сияние, космические пульсирующие сферы.

## 5. Грабли, нюансы и критические правила (DOs and DON'Ts)

Любой агент, вносящий изменения в проект, **ОБЯЗАН** соблюдать следующие правила:

1. **Строгое разделение кода:**
   * Если задача касается **телефона / мобильной версии** $\rightarrow$ редактировать **ТОЛЬКО** файлы в `src_mobile/`. Ни в коем случае не трогать `src/main.js` или `app.js`!
   * Если задача касается **ПК-версии** $\rightarrow$ редактировать файлы в `src/` и `app.js`.

2. **Баг трансформации винила в Android WebView (КРИТИЧЕСКИ ВАЖНО):**
   * В движке Chromium внутри Android WebView **НЕЛЬЗЯ** ставить статический `transform` (например, `transform: translateZ(0)` для аппаратного ускорения) на элемент, у которого запущена CSS-анимация с другим типом трансформации (`transform: rotate(360deg)`).
   * Несовпадение типов трансформаций приводит к тому, что движок интерполирует их через матрицы идентичности, и вращение визуально **полностью замирает**.
   * Для винила используются только чистые правила: `transform-origin: 50% 50%`, `will-change: transform`, префиксы `-webkit-animation` и только `rotate(...)`.

3. **Сетевые запросы на мобайле не должны блокировать UI:**
   * Никогда не вызывать `window.AndroidNative.postJson(...)` прямо в UI-потоке без крайней необходимости, так как это синхронный вызов Java $\rightarrow$ приложение зависнет до ответа сети.
   * Все сетевые запросы в `mobile-bridge.js` сначала идут через неблокирующий `fetch()` с `AbortSignal.timeout(...)`, и только при сбое используется нативный мост.

4. **Питомцы (Pets) вырезаны:**
   * Ранее в ПК-версии были питомцы-компаньоны (`pets.js`). По прямому требованию автора они полностью вырезаны. Не восстанавливать и не предлагать их вернуть.

5. **Тестирование и проверка перед сдачей:**
   * После любых правок в JS: запустить проверку синтаксиса: `npm run check` (проверяет 25 файлов).
   * После правок в мобильной версии: собрать APK: `python scripts/build-android-apk.py`.

## 6. Шпаргалка для составления промтов другим агентам

Чтобы другой агент выполнял задачи быстро и без лишних вопросов, используй следующую структуру промта:

### Шаблон идеального промта:
```markdown
[КОНТЕКСТ]: Проект MintPy v5.3.8 (Дзэн-аудиоплеер).
[ЦЕЛЬ]: <Четко опиши, что нужно сделать или починить>
[ЦЕЛЕВАЯ ПЛАТФОРМА]: <ПК (каталог src/) ИЛИ Мобильная версия (каталог src_mobile/)>
[ФАЙЛЫ ДЛЯ ПРАВКИ]: <Перечисли конкретные файлы, например: src_mobile/main.js, src_mobile/styles.css>
[ОГРАНИЧЕНИЯ]:
- Windows native окружение (PowerShell).
- Никакого Linux/WSL.
- Не смешивать код ПК и мобилки.
- Для мобайла: проверять `npm run check` и пересобирать APK через `python scripts/build-android-apk.py`.
```

### Примеры эффективных промтов:

* **Пример 1 (Мобильный UI):**
  > «В мобильной версии MintPy (`src_mobile/styles.css` и `src_mobile/main.js`) нужно сделать кнопку паузы на главном экране крупнее и добавить эффект плавного масштабирования при нажатии. Не трогай файлы ПК-версии из `src/`. После правок запусти `npm run check` и собери APK через `python scripts/build-android-apk.py`».

* **Пример 2 (Импорт / Бридж):**
  > «В `src_mobile/mobile-bridge.js` нужно улучшить парсер ссылок Яндекс Музыки, добавив поддержку ссылок на артистов (`/artist/...`). Сохраняй результат в локальные плейлисты `localStorage`. Проверь синтаксис и пересобери билд».

* **Пример 3 (ПК-версия):**
  > «В ПК-версии MintPy (`src/main.js` и `app.js`) почини горячую клавишу Mute. Используй Electron IPC bridge. Не меняй файлы в `src_mobile/`».
